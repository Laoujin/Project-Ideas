My Second System

GoF Design Patterns was on the job. And it turned out pretty good, I applied a few patterns (Strategy and State mostly) and it made the code less error prone and easier to extend.</p> <p>Happy with my success, I was going to throw my pet project around and implement some design patterns. Not just for the sake of applying patterns, there were some real issues with the design that would not allow for some things I wanted to implement.</p> <p>Premature Optimization<br>Flyweight: Actually made the implementation (much) slower.</p> <p>What turned out to be real time-saver instead: Turning a Dictionary&lt;Point, Object&gt; to Dictionary&lt;int, Object&gt; (Both X and Y were constrained to be between 1 and 999)</p> <p>Singleton: This turned out to be a really, really bad decision. Not only did it turn out to not be a Singleton after all, it also turned into a super-global popping up everywhere in the code (It was also called ‘World’) and made adding UnitTests afterwards so much more difficult.</p> <p>To top it off, too many layers of indirection and mixed abstractions between those layers.</p> <p>And so I fell victim to the Second System Syndrome.</
